## 0. 技术结论的来源

以下结论**不是凭记忆**，而是实测得出：

```bash
godot --version                       # 4.7.2.stable.arch_linux.ed1daf0bf (2026-08-17)
godot --headless --dump-extension-api # 导出类数据库后逐项核对
```

核对结果：`TileMapLayer` 存在（继承 `Node2D`），属性含 `y_sort_origin`、`occlusion_enabled`、`collision_enabled`、`navigation_enabled`、`x_draw_order_reversed`；`TileMap` 仍在但官方标注 deprecated（属性只剩 5 个）；`YSort` 节点**不存在**（已删除）；`CanvasItem` 有 `y_sort_enabled` / `z_index` / `z_as_relative`。

## 1. 地形分层

**目标**：地面、装饰、立体物、角色、覆盖物互不串层，且立体物之间按 Y 正确遮挡。

### 1.1 分层表

| 层 | 节点类型 | `z_index` | `y_sort_enabled` | 内容 |
|---|---|---|---|---|
| BackgroundLayer | `Node2D` | `-20` | OFF | 远景、天空、纯色底 |
| GroundLayer | `TileMapLayer` | `-10` | **OFF** | 地面基础瓦片 |
| GroundDecorLayer | `TileMapLayer` | `-9` | **OFF** | 草、石子、地毯、血迹 |
| GroundShadowLayer | `TileMapLayer` | `-8` | **OFF** | 贴地椭圆影子 |
| YSortRoot | `Node2D` | `0` | **ON** | 排序容器（本身不画） |
| ├ ObjectsLayer | `TileMapLayer` | `0` | **ON** | 树、墙、家具、石堆 |
| └ Entities | `Node2D` | `0` | **ON** | Player、NPC |
| OverhangLayer | `TileMapLayer` | `10` | OFF | 树冠、屋檐、门框上沿 |
| Light/Weather | `PointLight2D` / `CanvasModulate` | `20` | OFF | 日夜、天气 |
| UI | `CanvasLayer` | — | — | HUD、对话、淡入淡出 |

### 1.2 为什么这样分

官方原文（`CanvasItem.y_sort_enabled`）：
> "If `true`, this and child `CanvasItem` nodes with a higher Y position are rendered in front of nodes with a lower Y position."
> "**Nodes sort relative to each other only if they are on the same `z_index`.**"

所以 `z_index` 是**跨层的硬顺序**，`y_sort_enabled` 只在同一 `z_index` 内互相比较。地面放负 `z_index` 就能保证「即使玩家走到地图最上端也不会被地面盖住」，同时树与角色的遮挡关系交给 Y 排序。

### 1.3 TileSet 登记表

| 项 | 值 | 用途 |
|---|---|---|
| Tile Size | `16×16` | 基座 |
| Physics Layer 0 | `terrain` | 墙、水的实心碰撞 |
| Physics Layer 1 | `trigger` | 水域、遭遇区（不阻挡） |
| Terrain Set 0 | `Grass` | 自动接边 |
| Navigation Layer 0 | `walkable` | 供 `NavigationRegion2D` Bake |
| Occlusion Layer 0 | `light` | 供 `PointLight2D` 投影 |
| Custom Data | `is_water: bool`、`is_grass: bool`、`encounter_zone: int` | 运行时查询 |

### 1.4 高台伪高度

`TileMapLayer.y_sort_origin`（**层级**属性）官方说明："This Y-sort origin value is added to each tile's Y-sort origin value. This allows, for example, to fake a different height level."

→ 需要「二层/高台」时整层加偏移即可，不要在同一层里混放不同高度的物件。

## 2. 树木正确遮挡

「树木遮挡」有三种不同含义，必须分开做。

### 2.1 A 深度遮挡（优先，M3 验收点）

**现象**：玩家在树干**后面** → 树盖住玩家；在前面 → 玩家盖住树。

**配置四步**：

1. `TileSet` 编辑器选中树 tile → **Rendering → Y Sort Origin** = 树干底部到瓦片顶部的像素偏移
   - 树贴图 `32×64`（2×4 格）→ 起始值 `62`，实机 F5 对着 ±2 微调
   - 数值别瞎猜：先用单格小树验证，再上多格大树
2. `ObjectsLayer.y_sort_enabled = true`
3. 父节点 `YSortRoot.y_sort_enabled = true`（**两级都要开，只开一个无效**）
4. 玩家/NPC 节点**原点必须在脚底**（用 `Sprite2D.offset.y` 补偿）

**为什么能工作**：官方 `TileMapLayer.rendering_quadrant_size` 说明 — "The quadrant size does not apply on a **Y-sorted** TileMapLayer, as **tiles are grouped by Y position** instead in that case." 即 Y 排序的瓦片层会按 Y 切块成独立绘制单元，因此能与兄弟节点（玩家/NPC）正确交错。

**同 Y 相邻树左右顺序怪** → 调 `TileMapLayer.x_draw_order_reversed`（官方："If `CanvasItem.y_sort_enabled` is enabled, setting this to `true` will reverse the order the tiles are drawn on the X-axis."）。

### 2.2 B 树冠遮挡

玩家走进树荫被树冠挡住看不见 → 树冠单独拆到 `OverhangLayer`（`z_index = 10`，固定盖在最上），配合 `Area2D` + `Tween` 把该树 `modulate.a` 降到 `0.4`。
进阶：写 shader 按玩家位置在树冠上挖洞。

### 2.3 C 光照遮挡

夜里/洞穴里树投下影子 → `TileSet` 的 **Occlusion Layer** 给树画遮挡多边形，场景加 `PointLight2D` + `CanvasModulate`。`TileMapLayer.occlusion_enabled` 默认为 `true`。

### 2.4 树的两实现方式

| | 做法 | 优点 | 缺点 |
|---|---|---|---|
| 瓦片树 | 树作多格瓦片放 `ObjectsLayer` | 性能好、画图快、遮挡自动 | 不能做风吹动画、不能单独交互 |
| 场景树 | `Node2D + Sprite2D` 实例化进 `Entities` | 可动画、可砍伐、可交互 | 需手调 `offset`，数量多性能差 |
| **混合（推荐）** | 大批量背景树用瓦片，剧情树用场景 | 兼得 | 需要两套美术切图规范 |

## 3. 人物对话

默认**自研最小版**，但在 autoload 里留一层 `dialogue_provider` 接口 —— 将来要换 [Dialogue Manager 4](https://github.com/nathanhoad/godot_dialogue_manager)（要求 Godot 4.6+，本项目 4.7.2 满足）时只改一个文件。

### 3.1 数据结构

`dialogue/data/*.tres`，文件名即 `dialogue_id`：

```gdscript
# 每一行
{ speaker, portrait, text,
  choices: [ { text, next, condition } ],
  next, on_end, flag_on_end }
```

### 3.2 播放链路

```text
玩家交互键 → Interactable(Area2D) 命中 → dialogue_trigger.gd
        → DialogueRunner.play(dialogue_id)
        → 读 *.tres → 对话框 UI → 结束后发信号
```

### 3.3 UI

`CanvasLayer → Panel` + 头像 + 名字 + `RichTextLabel`（`visible_ratio` 做打字机）+ 选项 `VBoxContainer`。

### 3.4 与其他系统的联动（易漏点）

- 开对话 → `player.input_locked = true`；NPC 切 `TALK` 状态并转向玩家
- 结束 → 恢复输入、NPC 延时 1s 回 `PATROL`；玩家 0.3s 防误触
- `game_state.set_flag("npc_village_01_talked")` 防重复触发；选项条件读旗标
- 必要功能：交互键推进、打字机跳过、ESC 关闭、本地化预留（`tr()`）

## 4. 开门与场景转换

### 4.1 Door 导出字段

```gdscript
@export_file("*.tscn") var target_scene: String
@export var target_spawn: StringName = &"default"
@export var trigger_mode: int      # WALK 走近自动 / INTERACT 按 E
@export var locked: bool = false
@export var transition: int        # FADE / INSTANT
```

开门表现：`AnimatedSprite2D` 播门开帧动画，或 `TileMapLayer.set_cell()` 换成「开门」瓦片，`await` 播完再切场景。

### 4.2 SceneRouter 流程

1. 锁玩家输入
2. `Tween` 黑幕淡入（`ColorRect.a: 0 → 1`）
3. `ResourceLoader.load_threaded_request()` 预加载目标场景（大地图必做，否则黑幕期间卡住）
4. `get_tree().change_scene_to_packed()`
5. 新场景 `SpawnPoints` 组里找 `name == target_spawn` 的 `Marker2D` → 摆玩家位置
6. **重置 `Camera2D`**（`limit_*`、`reset_smoothing()`），否则镜头会从旧地图滑过来
7. 淡出黑幕 → 解锁输入

### 4.3 三个必须处理的坑

1. **防重复触发**：玩家落在门口会立刻再次触发 → SpawnPoint 放门外 ≥1 格 + Door `armed = false`，玩家 `body_exited` 后才 `armed = true`（或落地后 0.3s 冷却）
2. **场景销毁**：`change_scene_*` 会销毁整个当前场景 → 所有跨场景数据必须在 `GameState`
3. **玩家持久化策略**：
   - ① 每场景自带一份 Player，靠 `GameState` 恢复属性（简单，**推荐起步**）
   - ② Player 常驻 Autoload + `World` 容器只换地图（无闪烁，后期重构）

反向门：目标场景里的门把 `target_spawn` 指回来，形成双向。

## 5. NPC 运动轨迹

| 档 | 节点 | 适用 | 说明 |
|---|---|---|---|
| ① 固定轨迹 | `Path2D` + `PathFollow2D` | 巡逻兵、绕圈、行商 | `loop = true`，`progress += speed * delta`，路点可插停顿。**零寻路开销，最稳** |
| ② 路点列表 | `Array[Marker2D]` + `move_and_slide` | 少量拐角、每点要停顿/朝向 | 自己写 |
| ③ 自动寻路 | `NavigationRegion2D` + `NavigationAgent2D` | 绕障追玩家、自由漫游 | `agent.set_target_position()` + `agent.get_next_path_position()` |

### 5.1 导航烘焙

`NavigationRegion2D` 选中 → **Bake NavigationPolygon**，直接用 `TileMapLayer` 的 navigation layer 生成可行走区。
**改了地形必须重烘**，否则 NPC 撞空气墙。

### 5.2 NPC 基类

`CharacterBody2D + enum { IDLE, PATROL, PATHFIND, TALK, WAIT }`，`match` 起步，复杂了再上 `AnimationTree` 状态机。
朝向动画：`AnimationTree + BlendSpace2D` 按 `velocity` 混合四/八向，或 4 帧 directional sprite。
NPC 原点同样必须在脚底（Y 排序要求）。

### 5.3 性能

- **不要给每个 NPC 单独烘 `NavigationPolygon`**，全场景共享一个 `NavigationRegion2D`
- 离屏 NPC 用 `VisibleOnScreenNotifier2D` 降频
- 可选（后期）：`GameState.hour` 驱动时间表，NPC 白天/夜晚出现在不同路点

## 6. 全局架构

```text
输入(Input Map) → Player/NPC 控制器 → move_and_slide
                                        ↓
                      Interactable(Area2D) ← 玩家交互键
                        ├→ DialogueRunner → dialogue/data/*.tres → UI
                        ├→ Door → SceneRouter → GameState → 换场景 → SpawnPoint
                        └→ 箱子/告示牌 → GameState 旗标

Autoload：GameState（数据） / SceneRouter（流程） / DialogueRunner（表现）
```

**单一数据源原则**：任何要跨场景存活的东西（旗标、背包、已聊过的 NPC、当前时间、玩家属性）= `GameState` 的字段 + `save()/load()` 用 `FileAccess` 或 `ConfigFile` 落盘。

## 7. 美术与瓦片规格

| 项 | 值 |
|---|---|
| TileSet Tile Size | `16×16` |
| 大物件 | 树 `32×64`(2×4格)、房子 `96×80`、水井 `32×48` |
| 角色贴图 | `16×32`，4 向 × 4 帧 = `64×128` 一张图 |
| viewport | `640×360`（可见 40 × 22.5 格） |
| window | `1280×720`（×2 整数倍） |
| 全局过滤 | `Nearest` |

本机**无 PIL / Aseprite / Krita / GIMP**，但有 **ImageMagick** → 占位素材用 `magick` 生成，真素材后续替换。
